Abaqus Integration

This guide explains how to use simcoon’s built-in constitutive models within Abaqus on Linux systems.

Overview

Simcoon provides ready-to-use UMAT bridge files in the software/ directory that allow you to use all simcoon constitutive models directly in Abaqus:

  • software/umat_singleM.cpp - Single mechanical model (selected by material name)

  • software/umat_singleT.cpp - Single thermo-mechanical model

  • software/umat_externalM.cpp - Template for adding custom external UMAT in C++

  • software/umat_externalT.cpp - Template for custom external thermo-mechanical UMAT

These files export an extern "C" umat_() function that Abaqus calls directly. The bridge:

  1. Converts Abaqus arrays to the simcoon Armadillo format (abaqus2smart_M())

  2. Calls simcoon’s select_umat_M() to run the model the material name (CMNAME, read whole) selects

  3. Converts results back to Abaqus arrays (smart2abaqus_M())

Note

This is the opposite of the external plugin system documented in External. Here, simcoon models run inside Abaqus. In the external plugin system, external UMATs run inside simcoon’s solver.

Prerequisites

Linux System Requirements

# Required packages (Ubuntu/Debian)
sudo apt-get install build-essential cmake
sudo apt-get install libarmadillo-dev liblapack-dev libblas-dev

# Required packages (RHEL/CentOS)
sudo yum groupinstall "Development Tools"
sudo yum install cmake armadillo-devel lapack-devel blas-devel

simcoon Installation

Ensure simcoon is built and installed using the provided install script:

cd simcoon
sh Install.sh -n 4

# The script will:
# - Build simcoon with CMake/Ninja
# - Install to $CONDA_PREFIX (your conda environment)
# - Install the Python package
# - Optionally run tests

# To skip tests:
sh Install.sh -t -n 4

Using umat_singleM (Recommended)

This is the simplest approach: the model is selected by the material name in your Abaqus input file (the CMNAME token up to its first blank: five letters or a _closed name, the _R suffix aside; a descriptive tail such as EPICP_STEEL falls back to the first five letters).

Step 1: Compile the UMAT

cd simcoon/software

# Compile to shared library (using conda environment)
g++ -shared -fPIC -std=c++17 -O2 -o libumat_simcoon.so umat_singleM.cpp \
    -I$CONDA_PREFIX/include \
    -L$CONDA_PREFIX/lib -lsimcoon \
    -larmadillo -llapack -lblas

Step 2: Configure Abaqus environment

Create or edit your abaqus_v6.env file:

import os
conda_prefix = os.environ.get('CONDA_PREFIX', '/path/to/conda/env')

# Add library paths
os.environ['LD_LIBRARY_PATH'] = conda_prefix + '/lib:' + os.environ.get('LD_LIBRARY_PATH', '')

Step 3: Run Abaqus

abaqus job=mymodel user=libumat_simcoon.so

Material definition in Abaqus input file

The material name selects the constitutive model (the whole CMNAME token; Abaqus upper-cases names, so EPICP_CLOSED reaches EPICP_closed):

*MATERIAL, NAME=ELISO
*DEPVAR
5
*USER MATERIAL, CONSTANTS=3
** E, nu, alpha
70000., 0.3, 1.2e-5

*MATERIAL, NAME=EPICP
*DEPVAR
7
*USER MATERIAL, CONSTANTS=5
** E, nu, alpha, sigma_y, H
210000., 0.3, 1.2e-5, 200., 1000.

Using umat_singleT (Thermo-mechanical)

For coupled thermo-mechanical analysis with heat generation:

g++ -shared -fPIC -std=c++17 -O2 -o libumat_simcoon_T.so umat_singleT.cpp \
    -I$SIMCOON_DIR/include \
    -L$SIMCOON_DIR/lib -lsimcoon \
    -larmadillo -llapack -lblas

The thermo-mechanical version provides:

  • Mechanical tangent ddsdde (the Abaqus material Jacobian, see below)

  • Thermal stress tangent ddsddt (\(\partial \boldsymbol{\sigma} / \partial T\))

  • Heat flux derivative drplde (\(\partial r / \partial \boldsymbol{\varepsilon}\))

  • Heat capacity drpldt (\(\partial r / \partial T\))

  • Heat generation rate rpl

The simcoon kernels return the heat of the increment \(r\) (storage included, see Read the results); umat_singleT divides it and its derivatives by dtime to give Abaqus the rates it expects (zero at dtime = 0).

The whole thermomechanics stays in simcoon: rpl carries the complete heat of the model, \(r = \Delta\gamma_{loc} - T_{n+1} \Delta\eta\), i.e. the dissipation, the thermoelastic and latent couplings and the heat storage, and drpldt the matching heat capacity. The heat follows from the free energy of the law; it is not a Taylor-Quinney fraction of the plastic work, the stored energy \(W_m^{ir}\) does not heat the material. Therefore, with these UMATs:

  • set *SPECIFIC HEAT to a negligible value, otherwise the storage is counted twice;

  • do not use *INELASTIC HEAT FRACTION.

An adiabatic analysis then reads rpl = 0 exactly, as in the simcoon solver.

Geometric nonlinearity (NLGEOM)

Under NLGEOM the bridges run the law on the deformation gradient, exactly as the simcoon solver and fedoo do: DFGRD0 and DFGRD1 give the kinematics, STRAN, DSTRAN and DROT play no part, and every law of the finite-strain dispatch is available, the hyperelastic ones included. The material name chooses the kinematic form:

  • EPICP (the law name alone): the total form, the logarithmic strain \(\ln\mathbf{U}\) read from DFGRD1 with its dual stress. It keeps no kinematic history (*DEPVAR unchanged), satisfies the first law exactly and is exactly objective;

  • EPICP_R: the rate form (log_R, corate_type = 3), the accumulated \(\ln\mathbf{V}\) and its frame. These are history quantities: the last 15 STATEV entries hold them (see State Variables Layout).

The law is the whole CMNAME token (up to the first blank), _R excluded; a longer name such as EPICP_closed (the dedicated closed-form kernel, the plain name running the modular engine) is read as such, EPICP_closed_R being its rate form. A token longer than five letters that names no law and does not end with _closed carries a descriptive tail: its first five letters select the law (EPICP_STEEL runs EPICP, EPICP_STEEL_R its rate form), with one warning per name on the error stream. A token that then still names no law stops the analysis.

The outputs follow Abaqus’s definitions:

  • STRESS is the Cauchy stress \(\boldsymbol\sigma = \boldsymbol\tau/J\) in the global basis (the law works with the Kirchhoff stress \(\boldsymbol\tau\) per reference volume);

  • DDSDDE is the Jacobian Abaqus defines with the Jaumann rate of the Kirchhoff stress,

    \[\mathbf{C}^{\text{Abaqus}} = \frac{1}{J}\frac{\partial \Delta(J\boldsymbol{\sigma})}{\partial \Delta\boldsymbol{\varepsilon}},\]

    obtained from the law’s tangent through \(\partial\mathbf{S}/\partial\mathbf{E}\) (smart2abaqus_finite_M). It is exact in the total form; the rate form’s tangent ignores the variation of the log_R frame increment (a few \(10^{-3}\), enough for the global Newton loop);

  • in a coupled temperature-displacement step, the heat goes out per unit current volume and time, the measure Abaqus integrates over the deformed body: with \(r\) the heat of the increment per reference volume,

    \[\mathrm{RPL} = \frac{r}{J\Delta t}, \qquad \mathrm{DRPLDT} = \frac{1}{J\Delta t}\frac{\partial r}{\partial\theta}, \qquad \mathrm{DDSDDT} = \frac{1}{J}\frac{\partial\boldsymbol\tau}{\partial\theta},\]

    and DRPLDE the derivative of RPL for Abaqus’s strain increment (\(\delta\mathbf{E} = \mathbf{F}^{T}\delta\boldsymbol\varepsilon\,\mathbf{F}\), \(\delta J = J\,\mathrm{tr}\,\delta\boldsymbol\varepsilon\)), so that \(\int \mathrm{RPL}\,\mathrm{d}v\,\Delta t = \int r\,\mathrm{d}V_0\). Wm and Wt in STATEV stay per reference volume. These are the densities sim.umat_T(..., tangent_output="spatial") returns, times \(1/\Delta t\) (see In-memory Python solver): an updated-Lagrangian Python coupler and this bridge integrate the same heat.

Rules for the input file under NLGEOM:

  • do not define *EXPANSION: the thermal expansion belongs to the simcoon law, and Abaqus would remove its own thermal strain from DSTRAN;

  • do not use *ORIENTATION on these materials: Abaqus would express STRESS and DFGRD in a basis rotating with the material, while the bridge returns global components (the laws’ own anisotropy axes come from their properties and follow the material inside simcoon);

  • surface convection and radiation stay Abaqus’s (*FILM, *RADIATE): the UMAT provides the volumetric heat only;

  • *USER MATERIAL, UNSYMM=YES keeps the coupling terms (DDSDDT, DRPLDE) and the non-symmetric part of the Jacobian in the coupled Newton loop; without it Abaqus symmetrizes them.

The finite route serves every (NDI, NSHR) state. With three direct components (3D, plane strain, axisymmetric) the law runs on DFGRD0 / DFGRD1 as they come. For a condensed state (plane stress and shells, beams, trusses) the host’s free components of the deformation gradient are placeholders: the material point owns its free stretches through the strain it keeps in STATEV (the stress-free strain slots right after the energies, as in the corotational route; the thickness strain \(\varepsilon_{33}\) and the transverse shears for plane stress), rebuilds \(\mathbf{F}\) from them (condensed_F: \(\exp(\ln\mathbf{V})\,\mathbf{R}\) with the free components of \(\ln\mathbf{V}\) from the strain state, or \(\mathbf{R}\exp(\mathbf{H})\) under the total form) and solves them by a Newton on the free components of the box strain increment, the stress the law returns vanishing there (solve_condensed, two to four evaluations of the law per increment). The kept kinematics are formed with the free stretches of the start of the increment: exact when the free directions are principal (plane stress), second order otherwise. DDSDDE is the statically condensed box tangent, converted to the Jaumann Jacobian as in 3D. Steps without NLGEOM (Abaqus then hands DFGRD1 as the identity), the custom-model bridges and the mechanical laws that only exist in small strain (SMADI, LLDM0, the micromechanics schemes, …) keep the corotational route below; so does a law the total form does not serve (HYPOO) unless its name carries _R.

Corotational route. Abaqus then integrates the UMAT in its corotated frame: STRESS and STRAN are rotated by Abaqus before the call (DROT is the rotation increment, used here to rotate the tensorial state variables), DSTRAN is the logarithmic strain increment, and STRESS is the Cauchy stress. Abaqus defines DDSDDE as above, and since \(\mathrm{d}J = J\,\mathrm{tr}(\mathrm{d}\boldsymbol{\varepsilon})\),

\[\mathbf{C}^{\text{Abaqus}} = \frac{\partial \boldsymbol{\sigma}}{\partial \boldsymbol{\varepsilon}} + \boldsymbol{\sigma} \otimes \mathbf{I} .\]

The kernels return the first term, the corotational tangent \(\partial \boldsymbol{\sigma} / \partial \boldsymbol{\varepsilon}\); smart2abaqus_M (and the thermomechanical smart2abaqus_T) add the symmetric part of \(\boldsymbol{\sigma} \otimes \mathbf{I}\), which is what the default symmetric solver of Abaqus keeps (abaqus_jacobian in fea_transfer.hpp). This term does not change the stress, hence not the converged solution: it restores the quadratic convergence of the global Newton loop when \(\sigma / E\) is not small (elastomers, shape memory alloys). It is added only for NLGEOM steps and for the cases with three direct components. Without NLGEOM the Jacobian is the kernel tangent, so linear-perturbation procedures (*FREQUENCY, *BUCKLE) see the right stiffness; plane stress and 1D take the condensed tangent as it is, the element owning the thickness change (on the finite route, its Jaumann form of the condensed box tangent).

Plane stress, shells, beams and trusses

The bridges accept every (NDI, NSHR) state Abaqus passes: plane stress and shells (2, 1), shells with transverse shear (2, 3), trusses (1, 0) and beams such as B31 (1, 2) (11, 12, 13), next to the 3D, plane-strain and axisymmetric ones (NDI = 3). The NTENS components of STRESS, STRAN and DDSDDE map in Abaqus order to the simcoon components (the direct ones, then the shears 12, 13, 23).

With NDI < 3 the other components are stress-free and Abaqus does not give their strain. The material point solves it: the simcoon law always runs 3D, and a Newton iteration on its own tangent finds the strain that makes those stress components vanish, each evaluation integrating the whole increment from the start state (condensed_state.hpp, select_umat_M / select_umat_T). The converged point is the 3D law itself on the condensed state, for every law (plasticity, viscoelasticity, damage, SMA, MODUL), and DDSDDE (with DDSDDT, DRPLDE, DRPLDT in the thermomechanical bridge) is its exact condensed derivative whenever the law’s 3D tangent is exact: the global Newton keeps its quadratic convergence. The solved strain is kept in STATEV right after the energies (6 - NTENS values, simcoon order, rotated with DROT as Abaqus rotates STRAN), so each increment solves only its change: for plane stress, the thickness strain and the transverse shears (\(\varepsilon_{33}, \gamma_{13}, \gamma_{23}\)). The cost is two to four evaluations of the law per increment (more for a law whose 3D tangent is approximate, such as SMADI under tangent_mode = 2); a point that does not converge asks for a smaller increment through PNEWDT. The custom-model bridges (umat_externalM / umat_externalT) wrap external_umat the same way, so a custom law is written 3D only.

Using umat_externalM (Custom Model)

If you want to implement a custom constitutive model in C++:

  1. Copy software/umat_externalM.cpp to your working directory

  2. Implement your model in the external_umat() function

  3. Compile and link:

g++ -shared -fPIC -std=c++17 -O2 -o libumat_custom.so umat_externalM.cpp \
    -I$SIMCOON_DIR/include \
    -L$SIMCOON_DIR/lib -lsimcoon \
    -larmadillo -llapack -lblas

The external_umat() signature receives simcoon-format data:

void external_umat(
    const vec &Etot,      // Total strain
    const vec &DEtot,     // Strain increment
    vec &sigma,           // Stress (output)
    mat &Lt,              // Tangent modulus (output)
    const mat &DR,        // Rotation increment
    const int &nprops,    // Number of properties
    const vec &props,     // Material properties
    const int &nstatev,   // Number of state variables
    vec &statev,          // State variables (input/output)
    const double &T,      // Temperature
    const double &DT,     // Temperature increment
    const double &Time,   // Step time
    const double &DTime,  // Time increment
    double &Wm,           // Mechanical work (output)
    double &Wm_r,         // Recoverable work (output)
    double &Wm_ir,        // Irrecoverable work (output)
    double &Wm_d,         // Dissipated work (output)
    const int &ndi,       // Number of direct components
    const int &nshr,      // Number of shear components
    const bool &start,    // First increment flag
    double &tnew_dt       // Suggested time step ratio (output)
);

Why extern “C” works

The extern "C" declaration:

  1. Disables C++ name mangling - The function is exported as umat_ exactly

  2. Uses C calling convention - Compatible with Fortran calling convention

  3. Standard types only - double*, int*, char* work universally

Abaqus looks for the symbol umat_ in the shared library - it doesn’t care if the library was compiled from Fortran or C++.

State Variables Layout

simcoon uses a specific layout for state variables (statev array):

statev[0]                - Wm (total mechanical work)
statev[1]                - Wm_r (recoverable work)
statev[2]                - Wm_ir (irrecoverable work)
statev[3]                - Wm_d (dissipated work)
statev[4:4+nC]           - Stress-free strain components (NDI < 3 only, nC = 6 - NTENS)
statev[4+nC:...]         - Model-specific state variables (nstatev_smart of them)
statev[nstatev-15:]      - Rate form only (name suffix _R): the accumulated box strain
                           (6, Voigt) and the log_R frame rotation (9, column-major)

Set *DEPVAR in your input file to nstatev_smart + 4 + nC: the four work quantities come first, then the solved stress-free strain when NDI < 3 (nC = 0 for 3D, plane-strain and axisymmetric elements, 3 for plane stress and B31 beams, 5 for trusses), then the model’s own variables (the same layout as the Ansys ustatev when nC = 0, see Ansys Integration). The thermomechanical bridge stores the three thermal energies Wt, Wt_r, Wt_ir after Wm: *DEPVAR is then nstatev_smart + 7 + nC. A material whose name carries the _R suffix (rate form under NLGEOM) needs 15 more. For example, EPICP (8 variables) in a 3D element needs *DEPVAR = 12, and EPICP_R needs 27. The bridge checks that *DEPVAR is at least its own share (here 4, or 19 with _R); it cannot know how many variables the model itself needs, so a *DEPVAR that is too small for the model goes unnoticed.

What happens when the UMAT fails

The bridge never lets a C++ error reach Abaqus (that would kill the job without explanation). It prints the cause in the job log (.log), prefixed by simcoon UMAT:, and then does one of two things:

  • The increment is too large (for example a trial deformation gradient the model cannot handle, or a matrix logarithm that fails): it sets PNEWDT = 0.5, and Abaqus retries the increment with a smaller time step. The message ends with step cut requested.

  • The input is wrong (an unknown material name, a *DEPVAR smaller than the bridge’s share, an unsupported element or option): a smaller increment would not help, so the job stops at once through the Abaqus utility XIT (the .msg and .sta files are closed properly). The message ends with the analysis stops; fix the input file and resubmit.

The bridge library therefore leaves the symbol xit_ to Abaqus, which resolves it when it loads the user subroutine.

Troubleshooting

Compilation errors

# Check include paths
ls $SIMCOON_DIR/include/simcoon/

# Check library exists
ls $SIMCOON_DIR/lib/libsimcoon.*

Runtime library errors

# Check library path
echo $LD_LIBRARY_PATH

# Check dependencies of your UMAT
ldd libumat_simcoon.so

# Look for missing libraries
ldd libumat_simcoon.so | grep "not found"

Symbol not found errors

# Verify umat_ symbol is exported
nm -D libumat_simcoon.so | grep umat_
# Should show: T umat_

Convergence issues

  • Check that *DEPVAR matches nstatev_smart + 4 + nC (+ 7 + nC thermomechanical, + 15 with the _R suffix)

  • Verify material properties are in correct units

  • Start with small load increments

  • Check the tangent modulus is properly computed (symmetric, positive definite for elastic)

Debugging

Add debug output in the bridge code:

#include <fstream>

// In umat_() function, after abaqus2smart_M():
std::ofstream debug("umat_debug.log", std::ios::app);
debug << "=== Increment " << kinc << " ===" << std::endl;
debug << "Material: " << umat_name << std::endl;
debug << "T = " << rve_sv_M->T << ", DT = " << rve_sv_M->DT << std::endl;
debug << "Etot: " << rve_sv_M->Etot.t();
debug << "DEtot: " << rve_sv_M->DEtot.t();
debug.close();
